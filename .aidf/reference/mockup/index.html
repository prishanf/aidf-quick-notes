What to exercise

Replace this list with the questions this design gate is actually asking. A reviewer who has to guess will review the wrong thing.

  • Is the table scannable at 32 rows? Is the column order right?
  • Do negative amounts read clearly without relying on colour alone?
  • Narrow the window to < 40rem: does the table scroll in its own container, and does the page body stay put?
  • Tab through Records with the keyboard only. Is focus visible and the order sensible?
  • Are the empty state and the filtered-to-nothing state distinguishable, with the right recovery in each?
  • Toggle Theme: does anything become unreadable in dark mode?

Feedback goes in the design document

Nothing is built yet, so layout, flow, and scope can still change freely and cheaply. Record feedback in the design doc and re-approve — not on a pull request, which does not exist.
