# AIDF Quick Notes v1.0.0

Second integrated release from `develop`: edit a note (PR #3) and Markdown-formatted note bodies (PR #4), on top of v0.1.0's create/list/delete.

**Production approval:** not yet granted — this document is prepared for review. See Eligibility below for one open gap (Feature 4 UI QA sign-off) before requesting production cut.

## Highlights

- Notes can be edited in place from the home-page list, with title and/or body updated independently.
- Note bodies support Markdown — headings, bold/italic, links, lists, code, and blockquotes render as formatted HTML everywhere a body is shown, with a Write/Preview toggle on both the create and edit forms.
- Raw HTML or script typed into a body is always escaped to visible text, never executed; unsafe-scheme links (`javascript:`, `data:`) never become clickable — verified by both automated tests and independent AI review.

## Added

- Edit a note: inline row edit on the home page, `PATCH /api/notes/:id` with partial title/body updates, `updatedAt` advanced on save, `createdAt` unchanged.
- Markdown-formatted note body: safe CommonMark subset rendering (`app/utils/markdown.ts`, `markdown-it` with `html: false`) everywhere a body is shown; Write/Preview toggle on the create form and the inline edit form.

## Changed

- Upgraded vendored AIDF to 5.1.1: design agents now extend one shared mockup package per screen instead of copying scaffolding per feature.
- Design mockups consolidated: create/list/edit/delete/Markdown-preview now live in one shared `docs/design/mockups/notes/` package (token layer symlinked to the app); the per-feature scaffold copies from Features 1–3 were retired.

## Fixed

- Concurrent-delete during edit: saving an edit on a note that another caller deleted in the meantime now shows a not-found alert instead of silently failing (`371a7ba`, part of Feature 3).

## Upgrade notes

### Migration

None. Neither Feature 3 (edit) nor Feature 4 (Markdown body) changes the `notes` schema — both write to the same `title`, `body`, `updated_at` columns established in v0.1.0. Existing SQLite files need no new migration beyond what v0.1.0 already required (`npm run db:migrate`).

### Compatibility

- Same runtime shape as v0.1.0: local single-process Nuxt/Nitro, SQLite file at `SQLITE_PATH` (default `./data/notes.sqlite`), no authentication.
- **Behavior change to review before upgrading:** because Feature 4 has no stored plain-text/Markdown flag, **existing notes may render differently** once this ships if their body happens to contain Markdown-significant characters (a line starting with `#`, `*like this*`, backticks, a leading `-`, etc.). No data is rewritten — this is a render-time interpretation change only. See ADR 0003.
- New runtime dependency: `markdown-it@14.3.0` (MIT) + `@types/markdown-it` (dev). No new network calls, no new vulnerabilities per `npm audit`.

### Rollback

| Layer | Procedure |
|---|---|
| App / API / UI | Redeploy or checkout the prior `main` revision (`d62b6b1`, v0.1.0). Stops serving the edit UI, `PATCH` route, and Markdown rendering. |
| Schema | No migration in this release; nothing to roll back at the data layer. |
| Data | `title`/`body` are unchanged in shape; a rollback to v0.1.0 code still reads v1.0.0-written rows correctly (same columns, same types). |
