# AIDF Quick Notes v0.1.0

First integrated release from `develop`: create/list notes (PR #1) and delete a note (PR #2).

**Production approval:** granted by prishanf (2026-07-28) — explicit instruction to commit and push this release to `main`. Remaining Feature 2 Preview UI QA / label gaps are accepted follow-ups, not blockers for this cut.

## Highlights

- Local notes home page: create a note, see the list newest-first, delete with confirm.
- SQLite persistence via Drizzle; notes survive process restart after `npm run db:migrate`.

## Added

- Create and list notes (`GET`/`POST /api/notes`) with empty, loading, validation, and server-error UI states.
- Delete a note (`DELETE /api/notes/:id`) with confirm dialog, deleting state, and delete-error feedback; last delete restores empty state.
- Bootstrap: Nuxt 4, Tailwind v4 tokens, Drizzle/SQLite, AIDF 5.0.0 gates, health endpoint.

## Changed

- None relative to prior production (`main` remains bootstrap-only).

## Fixed

- None.

## Upgrade notes

### Migration

1. Checkout `release/v0.1.0` (or this revision) after the release branch is cut.
2. Install: `npm ci`
3. Apply schema (required once per SQLite file): `npm run db:migrate`
4. Start: `npm run dev` (or production start after build)
5. Migration artifact: `server/database/migrations/0000_parched_leo.sql` — additive `notes` table + `created_at` index.
6. Plan: `docs/migrations/001-create-notes.md`

Feature 2 adds **no** schema change (hard delete of existing rows only).

### Compatibility

- Local single-process Nuxt/Nitro; SQLite file at `SQLITE_PATH` (default `./data/notes.sqlite`).
- No authentication: any local caller that can reach the server can read/write/delete all notes.
- Delete is irreversible (no soft-delete, trash, or undo).

### Rollback

| Layer | Procedure |
|---|---|
| App / API / UI | Redeploy or checkout prior `main` revision (`7a6761e` bootstrap). Stop serving Feature 1–2 routes. |
| Schema | Forward-only policy. Do **not** edit released migration SQL. To abandon the table: stop the app, retain a copy of the SQLite file as recovery point, then remove or replace the DB file and run migrations appropriate to the rolled-back revision. |
| Data loss on delete | Individual hard deletes cannot be undone without a prior file backup. Capture a SQLite file copy before production cut if any notes must be recoverable. |
